# General questions and answers

Some questions don't really fit anywhere, so I have put them in this section.

## My feature or change request is too niche, what do you mean by that?

Every now and then there is a "niche" request for Firefly III or the data importer. Such requests are generally not honored. The requested change will not be made, and I will not accept a PR to do it for me. But what is a "niche request", and why won't I accept them?

As a general rule, a feature or an enhancement has to make peoples lives better by virtue of existing. For example, Firefly III allows you to quick-select a quarterly report range. The data importer connects to a variety of third party importers. That is useful. Even if you don't use it. You know what it does and why it is there. Opposed to that, many requested features or changes follow this pattern:

1. A user runs into a problem, Problem X.
2. To solve the problem, a new feature or option is proposed, to prevent them (and others) from running into Problem X.
3. It is _impossible_ for you to appreciate or understand the new feature until you also run into Problem X, at which point you must:
    1. Learn that this is in fact "Problem X".
    2. Learn from the documentation or by sheer will that this has been fixed in the past, and has a solution.
    3. Apply the solution to your Problem X, by changing the setting or using the new feature.
    4. Undo whatever you did previously, and do it again but this time with the fix for Problem X applied.

If this continues unchecked, and all the Problem Xs gets solved all the time by way of new features and settings, it means that Firefly III will become a mass of features, options, settings, choices and enhancements none of which bring value to the end user until they actually run into the associated problem and make the mental leap to the existing solution. 

This is what kills other products. A massive pile of check boxes, system settings, environment variables and tutorials to make the product do _exactly and only exactly_ what you want. This enormously increases the maintenance and support burden because each and every new feature must be maintained, tested and documented. All the while, people will continue to ask about Problem X, unaware that a solution exists, because nobody ever reads documentation. As a bonus, many people will apply the wrong solution to Problem X and run into even more problems, greatly increasing the maintenance and support burden.

Firefly III will not become such a product. It will remain it's crappy self, with missing features and missing options. But whatever options it offers, they will make sense and they will be useful. That means that the product does not exactly do what you need it to do. Sorry about that.
